# Scope ld_desktop around standard registration artifacts

`ld_desktop` will support desktop integration by standards-backed registration artifacts rather than by separate GNOME, KDE, Xfce, bare-window-manager, or Windows-shell public APIs. The coherent first expansion is a preferred desktop-bundle path plus individual effect calls for autostart, desktop entries, icons, MIME declarations and associations, default applications, URL protocol handlers, database/update activation plans, and uninstall cleanup reports; runtime shell opening and single-instance activation stay outside this tranche. This keeps the surface small while allowing Desktop Flavor tests to verify GNOME, KDE, Xfce, bare window-manager, and Windows 10/11 behavior honestly through capability reporting, staged writes, dry-runs, and explicit activation steps.
