# Windows Feature Matrix

This matrix tracks how surveyed repositories use Windows-specific features. It captures usage requirements first; abstraction design comes later.

The entries below combine first-pass project signals with the first source-level audit batch. "Seen" notes are examples from the cloned source trees, not an exhaustive inventory.

| Feature | Repositories | Common APIs/types to verify | Typical purpose | Coupling depth | Linux requirement implied | Notes |
|---|---:|---|---|---|---|---|
| Windowing and message loop | Notepad++, WinMerge, AutoHotkey, Rufus, WinSCP, Files, wxWidgets | `HWND`, `HINSTANCE`, `WNDPROC`, `CreateWindowEx`, `SendMessage`, `PostMessage`, `WM_*`, MFC/VCL/WinUI equivalents | Main windows, dialogs, editor controls, event dispatch, embedded controls | High | Toolkit-backed window/event abstraction or application-specific migration | Seen in Notepad++ `NppDarkMode.cpp`/`WinControls`, WinMerge `MainFrm.*`, AHK `application.cpp`/`script_gui.h`, Rufus `ui.c`/`rufus.c`, WinSCP `WinMain.cpp`, wxWidgets `src/msw/*`. Likely too broad for first module except native-handle policy/capability docs. |
| Registry/settings | ShareX, Greenshot, Rufus, Files, WinSCP, Open-Shell, mRemoteNG, System Informer, Qt | `RegOpenKeyEx`, `RegQueryValueEx`, `RegSetValueEx`, `HKEY_*`, .NET registry APIs, installer `.reg` behavior | Preferences, install state, startup integration, shell/default-app integration, file tags, portable mode | Medium | XDG config, INI/JSON/TOML, explicit system-integration permissions | Seen in ShareX registry helpers/startup paths, Greenshot startup/Office/codec probes, Files registry source generator and default-file-manager settings. Split app config from privileged desktop integration. |
| File watching | ShareX, Files, Notepad++, WinMerge, Qt, libuv, wxWidgets | `ReadDirectoryChangesW`, `FindFirstChangeNotification`, .NET `FileSystemWatcher`, Qt/libuv/wx watcher APIs | Detect changed files, watched upload folders, folder compare refresh, project/session updates | Medium | inotify/fanotify/polling fallback, recursive-watch semantics, event coalescing rules | Seen directly in ShareX `WatchFolder.cs`, Files `RecycleBinWatcher.cs`/`ShellViewModel.cs`, libuv `src/win/fs-event.c` and `src/unix/linux.c`, wxWidgets MSW/inotify watcher headers. Strong first-candidate module. |
| Shell integration | Notepad++, WinMerge, ShareX, Greenshot, Rufus, WinSCP, Files, Open-Shell, mRemoteNG | `ShellExecute`, `SHGet*`, COM shell interfaces, Explorer extensions, context menus, file associations | Open URLs/files, Explorer context menus, default file manager behavior, send-to actions, elevation | High | xdg-open, portals, DBus, desktop entries, file-manager integration, optional unsupported states | Seen in Notepad++ `ShellExecute`, WinMerge `ShellExtension`, Greenshot Explorer/helper code, WinSCP drag extension, Files default-file-manager registry/regsvr32 flow. Split process/open-url from deep shell extension work. |
| Process launching | Notepad++, WinMerge, ShareX, Greenshot, AutoHotkey, Rufus, WinSCP, Files, StaxRip, Qt, libuv | `CreateProcess`, `ShellExecute`, `ProcessStartInfo`, `cmd.exe`, PowerShell, pipes | Run external tools, automation commands, terminal/shell actions, installers/helpers | Medium | `posix_spawn`, `fork`/`exec`, `$SHELL`, pipe/environment handling | Seen across WinMerge shell extension, ShareX/Greenshot helpers, Files terminal/default-manager setup, WinSCP `Tools.cpp`, libuv `uv_spawn` backends. Strong first-candidate if quoting/env semantics are explicit. |
| Dynamic library loading | Notepad++, WinMerge, AutoHotkey, Rufus, WinSCP, libuv, wxWidgets, System Informer, OBS, Qt, Scintilla | `LoadLibrary`, `GetProcAddress`, `FreeLibrary`, `.dll`, plugin manifests | Plugins, optional integrations, native backends, editor component loading, system DLL feature probes | Medium | `dlopen`, `dlsym`, `.so`, symbol/version policy | Seen in Notepad++ dark mode/plugin admin, WinMerge plugin/image/web diff, AHK `DllCall`, Rufus Windows DLL probes, WinSCP, libuv `uv_dlopen`, wxWidgets `wxDynamicLibrary`. First candidate, but plugin ABI compatibility remains out of phase one. |
| Clipboard and drag-and-drop | Notepad++, WinMerge, ShareX, Greenshot, WinSCP, Files, wxWidgets, mRemoteNG, KeePassXC, Qt, GLFW | Win32 clipboard APIs, OLE, COM drag/drop, `IDataObject`, `IDropTarget`, toolkit equivalents, WinRT `DataPackage` | Text/image/file transfer, screenshot workflows, upload/drop zones, file-manager operations | Medium to High | Toolkit-specific clipboard/DnD APIs, Wayland/X11 caveats, MIME types | Seen in Notepad++ `OpenClipboard`, WinMerge `Common/Clipboard.cpp`, ShareX/Greenshot clipboard helpers, Files `TransferHelpers`, WinSCP tools/VCL clipboard, wx OLE/GTK drag/drop. UI-adjacent, likely needs toolkit adapter rather than pure core. |
| Filesystem/path handling | Notepad++, WinMerge, Rufus, WinSCP, Files, ShareX, StaxRip, Qt, libuv, KeePassXC | drive letters, UNC paths, backslashes, attributes, long paths, temp dirs, file IDs, shell paths, WinRT `StorageFile`/`StorageFolder` | Open/save, compare folders, removable drives, config paths, external tool paths | Medium | `std::filesystem`, XDG paths, mount/device metadata, encoding policy | Seen everywhere, but Rufus/Files show that device and WinRT storage semantics are not just path strings. Strong first candidate only if scoped to config/path utilities and feature flags. |
| Single-instance IPC | AutoHotkey, WinMerge, WinSCP, Notepad++, ShareX, System Informer, Qt, libuv | `CreateMutex`, named pipes, `WM_COPYDATA`, window-message IPC, lock files | Reuse existing app instance, pass file paths/commands to running app | Medium | Unix domain sockets, DBus, lock files, activation protocol | Seen in AHK `CreateMutex`, WinMerge `WM_COPYDATA`, WinSCP `WM_COPYDATA` plus `CreateMutex`, libuv pipes. Strong first candidate because behavior is common and testable without full GUI, but activation UX may be toolkit-specific. |
| Printing | Greenshot, Notepad++, WinMerge, wxWidgets | GDI printing, print dialogs, printer device contexts, toolkit printing APIs | Print text, diffs, screenshots, reports | Medium | GTK/Qt print dialogs, CUPS, PDF/export fallback | Seen in Greenshot `PrintHelper.cs` and screenshot printing flows; wx has mature printing/DC abstractions. Future work unless Notepad++ POC specifically needs print early. |
| Common controls/dialog resources | Notepad++, WinMerge, Rufus, wxWidgets, Open-Shell, Qt | `.rc`, `DIALOG`, `MENU`, accelerators, `comctl32`, `TCM_*`, `LVM_*`, `TVM_*` | Menus, preferences, tab/list/tree controls, resource-defined dialogs | High | Toolkit UI rebuild, generated resources, migration tooling | Seen heavily in Notepad++, WinMerge, Rufus, wx MSW port. UI-adjacent; likely informs migration docs/tools more than first low-level modules. |
| Device/volume operations | Rufus, System Informer | `DeviceIoControl`, `SetupDi`, raw `CreateFile` device paths, kernel/service APIs | Removable media, formatting, process/system inspection, privileged operations | Very high | Application-specific Linux subsystem integration, udev, polkit, kernel APIs | Seen centrally in Rufus `drive.c`/`dev.c`. Important negative/boundary category: do not generalize as a first desktop library. |
